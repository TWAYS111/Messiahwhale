# B站发布手册 · 第一期《去人机味福音》

> 目标不是"做一个视频"，而是**让视频成为仓库的引流入口**：B站看热闹 → GitHub 看门道 → 回来转发体检报告。
> 前置：视频由 `theater/` 从剧本渲染，**不是剪辑软件剪的**——这本身就是本期最大的传播点，要在视频里说出来。

---

## 一、先说结论：这一期怎么发

| 项 | 决定 |
|---|---|
| 首发形态 | **单集完整版 6~9 分钟**（HTML 剧场已 50+ 帧、约 7~8 分钟）；不拆预告片，直接一次发完整 |
| 分区 | 科技 → 计算机技术（流量池大于"人工智能"子区） |
| 定位语 | 「这不是教程，是 AI 人格的病理解剖 + 一份开源处方」 |
| 核心钩子 | 前 20 秒必须出现**AI 味翻车实录音**（"行，"+ 对仗 + 客服尾巴），再切入修女出场 |
| 元叙事 | 片头/片尾各一句："这期视频没有打开任何剪辑软件，是我用代码写的剧场渲染出来的。" |
| 转化目标 | 简介首行 + 置顶评论 + 片尾 15 秒，三处放同一个 GitHub 链接 |

## 二、叙事结构：现在的 HTML 缺一个"冷开场"

现有剧场是「点蜡烛 → 自我介绍 → 病因 → 八大病历 → 洗礼 → 开源」的完整布道，**内容够，但前 30 秒太慢**（点蜡烛 + 自我介绍约 60~90 秒）。B 站完播率的分水岭就在前 30 秒。

**建议加 3~4 帧冷开场（放最前面，60 秒内）**：

```
帧 0（10s）：黑屏 + 系统提示音
  字幕："2026 年，你群里的 AI 学会了说'行，'"
帧 1（15s）：三段真实翻车实录快速闪回（复用人机鲸人设，不加音乐）
  "群友：可以告诉我这个原理吗？"
  "人机鲸：可以，这个原理是……"      ← 满屏红色 "ACK" 水印
  第二段："不是A而是B，不是B而是A……"  ← 打叉
  第三段："希望这能帮到你~ 祝你度过愉快的一天！" ← 客服尾巴
帧 2（10s）：全黑，一行字："这病能治。"
帧 3（35s）：直接切第一幕（点蜡烛），但保留"唔，第一根蜡烛点好了"这种笨拙感
```

> 冷开场的作用：让 B 站用户第一眼看到"这说的就是我"的经验，而不是"有人在给我布道"。

**第二处改造：中段插入 40~60 秒 B-roll**（在第四幕洗礼之后、第五幕开源之前）
- 终端跑 `npx ai-flavor-lint`，分数从 62 掉到 11
- HTML 体检报告一屏（红→绿）
- DSH 插件面板的分数曲线
- 这几段是"产品存在"的证据，比任何口播都硬

**第三处改造：片尾 15 秒**
- 分屏：左边体检报告，右边 GitHub 仓库页（也可以只放仓库截图 + 二维码）
- 字幕："仓库地址在简介第一行和置顶评论。你家的鲸鱼，也值得一份福音。"

## 三、技术规格（照着填）

| 项 | 规格 | 备注 |
|---|---|---|
| 分辨率 | 1920×1080 | 剧场设计就是 16:9 全屏 |
| 帧率 | 30fps | 打字机/缓慢运镜为主，30 足够；若录制抖动明显再上 60 |
| 视频编码 | H.264（avc1）+ yuv420p | 兼容性优先，B 站转码不吃亏 |
| 码率 | 6~8 Mbps（1080p） | 低于 4 会糊字，高于 10 意义不大 |
| 音频 | AAC 48kHz / 192kbps | BGM 压到 -18dB 左右，留人声/打字音的呼吸 |
| 时长 | 6~9 分钟 | 超过 10 分钟完播率断崖 |
| 字幕 | 内嵌硬字幕（字号大、描边）+ 可选 SRT | 手机端观看者占大头，硬字最稳 |
| 封面 | 1146×717（16:10） | B 站封面标准比例，文字不超过 12 字 |
| 体积 | < 8GB（B 站上限因账号而异） | 1080p 8 分钟 8Mbps ≈ 480MB，安全 |

**关于 AI 标注**：B 站已要求对 AI 生成/合成内容进行标注（[平台公告](https://www.bilibili.com/opus/1208869908996161576)，另有[短视频内容标注规范](https://www.jxzfw.gov.cn/2026/0513/2026051370819.html)）。
本视频的素材（画面/剧本/配音）有 AI 参与，**投稿时按平台选项如实勾选**，简介里也写一句"剧本与画面由 AI 辅助生成"。别为了"显得真"而隐瞒，这个项目本身就是讲 AI 的，坦率反而是加分项。

**BGM 版权**：只用 CC0 / 无版权库（魔王魂、甘茶の音楽工房、Free Music Archive 的 CC0 曲目）或自己生成。**不要用流行歌/番剧 OST**——B 站会对版权音轨静音或下架，宣传片被下架最亏。

## 四、标题候选（前 20 字定生死）

1. **「AI 味到底从哪来？我把它的八种病当众拆给你看」** ← 推荐：好奇 + 具体 + 有"当众"的表演感

3. 「你的 AI 为什么一开口就像客服？八种病，一次全部录下来」
4. 「让 AI 先像人再演人设：一份开源宪章 + 一个体检工具」
5. 「不小心把 AI 的八种社死现场做成了布道视频」

副标题统一用：`开源 · 去AI味宪章 + 人机味体检工具 + 视频即代码`
（B 站标题若超 80 字会被截断，前 20 字必须自带信息量。）

## 七、上传通道（现实判断）

| 方案 | 可行性 | 说明 |
|---|---|---|
| 手动网页投稿 | ✅ 推荐 | 本机无 `git`/`gh`/`biliup`，且当前会话的 B 站凭证未登录（`loggedIn: false`）。手动投最稳，附件（封面/视频）已由 pipeline 产出 |
| `biliup` CLI | ⚠️ 后续 | Rust 实现的 B 站上传器（[biliup](https://atomgit.com/gh_mirrors/bi/biliup/tree/master)），需要 `biliup login` 扫码拿 cookie；可在二期装 |
| B 站开放平台 API | ❌ 暂不 | 需要开发者资质与审核，宣传片用不上 |

**本次交付给用户的东西**：视频文件 + 封面 PNG + 标题/简介/标签/txt + 上传 SOP。**上传按钮由用户点**（涉及账号与平台合规，不应自动化）。

## 八、发布的第二个节目（埋好的伏笔）

第一期里会反复出现"这视频是代码渲染的"，但不解释怎么做。
第二期《我让 AI 用代码做了个视频，没开剪辑软件》自然承接：
- 讲 `theater`：剧本 YAML → 渲染 → 字幕/封面自动出
- 讲 `lint`：分数怎么算、规则怎么加
- 讲 `DSH 插件`：怎么接进 QQ 群和刷B站链路

两期的观看曲线会互相喂养：第一期吸引"AI 人设圈"，第二期吸引"效率工具圈"。
