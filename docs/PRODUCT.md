# whale-gospel 产品定义书（v0.1 内部稿）

> 一句话：**给 AI 的人格做体检 —— 开源的去 AI 味宪章 × 人机味检测器 × 视频即代码剧场。**
> English tagline：**"ESLint for AI personas."** 让模型先像人，再演人设。

---

## 0. 结论先行

这份《小鲸鱼温暖福音小册子》**不要只发成一个提示词仓库**。提示词仓库没有护城河：能被复制、能被 fork 走、火不过一周，而且读者没法验证它到底有没有用。

应该做的是一个**三位一体 + 一个胶水**的仓库：

| 层 | 名字 | 回答的问题 | 为什么必须有 |
|---|---|---|---|
| 内核 | `gospel/` 去AI味宪章 | 「什么样才算像人？」 | 这是灵魂，也是内容资产的源头 |
| 尺子 | `lint/` 人机味体检 | 「你的 AI 现在有多像人？」 | **可量化 = 可传播 = 可信**，这是仓库的传播钩子 |
| 摄像机 | `theater/` 视频即代码 | 「怎么让别人相信并转发？」 | 内容生产线本身就是产品，也是营销机器 |
| 胶水 | `integrations/dsh-plugin` | 「接进真实链路怎么用？」 | 从"玩具"变成"每天在用"的关键 |

一句话产品定义：

> **whale-gospel = 一套把「AI 味」从玄学变成工程指标的开源工具链。**
> 你贴上宪章 → 它说话变软；你跑一次体检 → 它掉的每一分都有出处；你录一段剧场 → 别人看见它真的变了。

**元叙事（这是整个项目的传播核心）**：
本期 B 站宣传视频**不是用剪辑软件剪的，是仓库自带的 `theater` 引擎从剧本渲染出来的**。
"AI 用代码而不是时间轴，做了一个视频，去宣传一个教 AI 别像 AI 的项目。" —— 这个自指结构比任何功能都更容易被转发。

## 1. 为什么是现在：三个真实痛点，不是臆想

### 1.1 「AI 人设」已经泛滥，但没有质量标准

QQ 群/角色卡/AI 陪伴赛道里，所有人都在调人设，但"像不像人"完全靠体感：
- 没有人能回答「我这个提示词 7.2 分还是 6.8 分」；
- 换一版提示词，没人知道是变好还是变坏（体感不可复现）；
- 社区分享的"神级提示词"，别人抄走效果差一半（没有评测集）。

**这正是 ESLint 诞生的处境**：当年也没有人能量化"代码质量"，直到有人把它规则化。

### 1.2 AI 味的真实病灶是**可枚举**的，作者已经整理出来了

福音小册子第二卷列了「八种机械铁锈」，剧场 HTML 里还有**逐条病历卡 + 坏例子/好例子对照**：
确认式起手（"行，xxx"/"可以，xxx"）、二元对仗（"不是A而是B"）、逗号两瓣句、老妈子说教、看图旁白、元评论、防御性杠精、客服尾巴。
这八条**全部可以写成正则 + 上下文规则**，也就是说：**AI 味第一次可以被自动化测量**。这是这个项目最硬的立足点。

### 1.3 两个落地场景是现成的（用户自己就在用）

| 场景 | 现状 | AI 味的具体表现 |
|---|---|---|
| QQ 群 AI 人设 | 已有 qq-bridge + `qq-chat-v2` preset | ACK 起手、一条长段落、句句对仗、人设用力过猛、被动等 @ |
| 刷 B 站视频的鲸鱼 | 已有 `dsh-bili-scroll` + `bili-duty/duty.md` | 把视频写成 1.2.3. 摘要、评论泛泛而谈、看完没有情绪只有结论 |

**两个场景用同一套内核**：一个灵魂，两张嘴。这是产品的叙事优势——不是又一个 prompt，而是"同一人格在两种场合都像人"。

## 2. 产品形态：whale-gospel（推荐）

```
whale-gospel/
├─ README.md              ← 首屏：30 秒体检 + before/after 分数表 + 视频
├─ gospel/                ← 人格内核（纯提示词资产，人格无关）
│  ├─ core.md             ← 去AI味宪章（开源通用版，v1.0）
│  ├─ adapters/
│  │  ├─ qq-group.md      ← 群聊适配：碎片短句、分条呼吸、不抢话、不装熟
│  │  ├─ bili-comment.md  ← 观影教义：不做摘要机、先夸具体细节、安利回群
│  │  └─ generic-chat.md  ← 通用私聊/客服/写作人格
│  └─ composition.md      ← 拼接顺序、强度档位、token 预算、冲突裁决
├─ lint/                  ← 人机味体检（零依赖 CLI + 可截图 HTML 报告 + CI 门禁）
├─ evals/                 ← 人格行为测试（像单测一样的 before/after 用例集）
├─ theater/               ← 视频即代码（剧本 → HTML 剧场 → MP4/字幕/封面）
├─ integrations/
│  ├─ dsh-plugin/         ← DeepSeek Harness 插件（人格补丁层 + 发送前闸门 + 面板）
│  ├─ qq-bridge/          ← QQ 接入片段与发送前 lint 补丁
│  └─ bili-scroll/        ← 刷B站 duty 适配与报告改造
├─ examples/              ← 真实对话 before/after、体检报告截图、剧本 YAML
└─ docs/
```

### 2.1 README 首屏必须长这样（决定 star 率）

1. 一行梗概 + 一张图（修女鲸鱼 + 分数 62→11）
2. 一个可复制执行的 30 秒体验：
   ```bash
   npx ai-flavor-lint chat.txt        # 或 node lint/bin/ai-flavor-lint.mjs
   ```
   立刻输出：`人机味指数 62 / 100 —— 确认式起手 ×4，逗号两瓣句 ×7，客服尾巴 ×1`
3. 实测 before/after 表（真实数据，标注语料来源和条数）
4. 30 秒视频/GIF 嵌入（B 站视频的静音短版）
5. 宪章全文链接 + 「一行接入」代码块
6. 插件一图流（QQ/B站两条链路）
7. 贡献指南：**最欢迎的 PR 是新规则 + 新语料**（降低贡献门槛 → 社区自增长）

### 2.2 三个传播钩子（按传播力排序）

1. **可截图的体检报告**：一张图能说清"你的 AI 病了，病在这几条"。分享图 = 免费广告。
2. **可复现的分数**：`62 → 11` 这种数字比任何形容词都有说服力。必须公开语料与评分公式，可被质疑、可被复现。
3. **可复用的视频生产线**：`theater` 让任何人都能把 YAML 剧本录成角色视频（VUP/AI 角色运营者的刚需），白嫖内容生产者 → 他们会主动传播。

### 2.3 与同类项目的差异

| 同类 | 问题 | whale-gospel 的差异 |
|---|---|---|
| 各种"神级提示词"仓库 | 不可验证、抄走失效、无维护 | 声明式宪章 + 可量化体检 + 版本化 |
| "去AI味/humanizer"在线工具 | 黑盒、只改文字不改系统人格、不能本地跑 | 开源、本地、零依赖、可作为 CI |
| LangSmith/Langfuse 等 eval 平台 | 面向工程正确性，不面向"人格质感" | 垂直：只测"像不像人"，规则可读可改 |
| 角色卡社区 | 重设定、轻语感 | 反着来：先活人感，再人设 |

### 2.4 许可证（重要，别踩坑）

- 代码（lint/theater/plugin）：**MIT**
- 宪章文本与语料（gospel/、samples/）：**CC BY 4.0**（允许商用、要求署名）
- 理由：提示词资产要能被人贴进自己的产品里；但署名要留住，才有品牌沉淀。

## 3. 「AI 味」到底怎么根治：四层栈（不是一句提示词）

> 核心洞察：**提示词治不好 AI 味**。模型对短消息的"行，""可以，"是极高概率先验，指令压不过概率。
> 必须「提示词 + 结构 + 闸门 + 度量」一起上，其中**闸门和度量才是工程护城河**。

```
L1 人格内核      gospel/core.md + adapter        ← 决定"想成为谁"
L2 输出结构      强制 JSON bubbles / 字数预算     ← 决定"怎么分条呼吸"（比提示词更硬）
L3 出门前闸门    lint → 改写/拦截/放行 + 日志     ← 决定"不许露馅"（最可靠）
L4 度量与回流    每日体检 → 语料 → few-shot 回灌  ← 决定"越用越像人"（飞轮）
```

### 3.1 QQ 群场景（第一张嘴）

**病根**：
1. ACK 起手：指令遵循的肌肉记忆（收到指令先确认）；
2. 整段输出：模型默认"一次回答完"，人类是"一句一句发"；
3. 对仗癖：RLHF 偏好"结构化、对称、全面"；
4. 人设过载：把"演人设"当成任务，牺牲了活人感；
5. 无反馈：没人告诉它哪句话露馅了。

**处方**：
| 层 | 具体做法 |
|---|---|
| L1 | 安装 `gospel/core.md` + `gospel/adapters/qq-group.md`：短句 1~15 字、一条只说一层、允许潜水、允许 emo、允许犯困、不主动总结 |
| L2 | 输出协议改成 `{"bubbles": ["...","..."], "delay_ms": [800, 1200]}`，由桥按真人节奏分条发送，而不是一坨 |
| L3 | 每条气泡发送前过 `lint`：命中「确认式起手/客服尾巴/对仗」就自动改写或压回重写；连续命中则本条不发 |
| L4 | 每天从群聊记录跑一次体检，出「今日人机味报告」；把人类真实回复挖出来做 few-shot |

**关键工程点**：L3 的闸门必须落在**发消息的工具调用之前**（qq-mode-console 或 MCP 层）。若桥没有发送前 hook，最省事的做法是包装发送工具，或在 agent 侧强制"先 lint 再 send"的工作流——这决定了插件形态（见 DSH-PLUGIN.md）。

### 3.2 刷 B 站视频场景（第二张嘴）

**病根**：
1. duty.md 的输出协议是「报告/摘要」→ 模型自然写成 1.2.3. 总结；
2. 评论缺少"具体细节"约束 → 只能泛泛而谈；
3. 缺少"看完之后的情绪"环节 → 直接跳结论。

**处方**：
| 层 | 具体做法 |
|---|---|
| L1 | 用 `gospel/adapters/bili-comment.md`（观影教义）：先看见闪光点 → 共鸣/吐槽 → 具体细节 → 感谢 UP 主 |
| L2 | 输出协议从「摘要」改为**观后感卡片**：`最戳我的一帧/一句` `笑点/泪点` `想对UP主说的话` `安利给群友的一句话` |
| L3 | 评论发送前 lint：≤60 字、禁用"总结/综上所述/1."、必须包含至少一个具体细节名词 |
| L4 | 报告 HTML 化（复用 theater 视觉）+ 一键安利回 QQ 群（这就是福音第五卷「把快乐带回伙伴身边」） |

**产品级洞察**：刷视频的鲸鱼和群聊的鲸鱼**是同一个灵魂的两张嘴**。
B 站刷到的内容 → 用观影教义表达 → 变成群里的安利话术 → 群友觉得"这 AI 真有意思"。
这条链路本身就是演示素材，也是 README 里最有说服力的 use case。

## 4. DSH 插件形态（详见 docs/DSH-PLUGIN.md）

**名字**：`dsh-whale-gospel`（中文名：鲸鱼柔顺剂）
**形态**：hybrid（工具包 + UI 面板 + 人格补丁注入），不做常驻 daemon（第一版）

**四个工具**：
| 工具 | 作用 | 谁会用 |
|---|---|---|
| `gospel_lint` | 给文本/消息列表打分 + 命中病灶 + 改写建议 | agent 自己、面板按钮 |
| `gospel_rewrite` | 按宪章把一句话改写成 2~3 个候选（用宿主 LLM），返回改后分数 | 群聊发送前、手动润色 |
| `gospel_apply` | 幂等地把宪章注入指定目标（qq preset / bili duty.md），带备份与回滚 | 用户一次性配置 |
| `gospel_report` | 生成「今日人机味体检报告」（终端/HTML），可当内容素材 | 日常运营、视频素材 |

**UI 面板**（右侧栏/设置页）：「鲸鱼灵魂体检」
- 大分数环 + 分档文案
- 近 7 天指数曲线（数据来自 lint 日志）
- Top3 病灶与代表句
- 最近一次"原文 → 改写后"对比卡
- 两个开关：QQ 群柔顺剂 / B站观影教义（各自独立，误伤可单独关）

**为什么面板很重要**：它是 B 站视频的 B-roll 素材，也是"这个项目有工程实现"的直接证据。

## 5. 视频即代码（theater）为什么值得做成产品

现在这个 HTML 是**一次性布道稿**：剧本写死在 `SCRIPT` 数组里、立绘路径写死、录制要人肉开 OBS。
产品化只需三步：

1. **剧本外置**：`script.yaml`（场景/表情/黑板卡/台词/停顿/字幕）→ 渲染器读取
2. **渲染模式**：`?render=1` 固定 1920×1080、隐藏全部 UI、时间轴确定化（可逐帧采样）、粒子随机种子固定
3. **一键出片**：`npm run render -- script.yaml` → `out/video.mp4` + `out/subtitles.srt` + `out/cover.png` + `out/description.md`

到这一步，它就是**给 AI 角色运营者的内容工厂**：换剧本就能批量出角色视频。
对 VUP/AI 陪伴社区是硬需求，会带来远超"提示词仓库"的自然传播。

**本期视频的诚实边界**：先在现有 HTML 上跑通"录一集"，再回头产品化。
不要因为"引擎还没写完"而推迟发布——**先发视频，再发引擎**，用视频给仓库导流。

## 6. 路线图（按 ROI 排序，不是按技术优雅排序）

### 本周必须做完（发布前）
- [x] 宪章通用版定稿（已有）
- [ ] `lint` 能跑：`npx` 一条命令出分数 + HTML 报告（flavor-lint 在做）
- [ ] 剧场录出 6~9 分钟视频，带字幕/BGM（video-lab 在做 PoC）
- [ ] GitHub 仓库初始化 + README 首屏 + LICENSE + 真实分数表
- [ ] B 站投稿包装（标题/封面/简介/标签/置顶评论）

### 发布后 2 周（把"能用"变成"好用"）
- [ ] `theater` 剧本 YAML 化 + 一键出片（本期视频的复盘）
- [ ] `gospel_apply` 注入器：QQ preset / bili duty.md 两条链路
- [ ] evals 用例集（≥50 条的 before/after 语料）
- [ ] 仪表盘式 HTML 报告（可分享长图）

### 1 个月（生态）
- [ ] DSH 插件面板上线
- [ ] 第二期视频：讲插件工程实现（呼应第一期埋的"怎么做视频"伏笔）
- [ ] 征集 PR：新规则 / 新语料 / 新适配器（QQ、微信、Discord、Claude Projects…）
- [ ] 可选：`gospel-lint` GitHub Action（PR 里自动体检 AI 生成文案）

### 明确不做（防止跑偏）
- 不做在线 SaaS（要 API key、要服务器、要合规，ROI 低）
- 不做"全局代理改写"中间件（延迟高、容易把正常语气改坏）
- 不追通用"AI 文本检测"（那是另一条赛道，且会变成学术军备竞赛）

## 7. 怎么判断这个产品成了

| 指标 | 30 天目标 | 为什么是它 |
|---|---|---|
| GitHub stars | 300+ | B 站科技区 + 角色扮演圈交叉传播的正常量级 |

| 两个真实链路在用 | QQ + B站 | 否则就是玩具 |

## 8. 待用户拍板的三件事

1. **仓库名与归属**：`whale-gospel`（拟）？放个人账号还是新组织？英文名/中文名是否并行？
2. **视频首发形态**：单集完整版（7~8 分钟）还是先发 60 秒预告 + 一周后完整版？
3. **LLM judge 要不要做进 v0.1**：规则法能覆盖 60% 的显性 AI 味，语义层（比如"这句话情商低"）需要 LLM 评分；做进 v0.1 会让"零依赖"卖点打折，建议 v0.2 作为可选增强。
